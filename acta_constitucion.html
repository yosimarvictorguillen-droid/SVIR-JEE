Acta de Constitucion del Proyecto

Nombre del ProyectoImplementacion del sistema SVIR-JEE (Sistema de Ventas e Inventario para Reposteria) para la empresa "Dulce Momento"
Gerente del ProyectoYosimar Guillen Espinoza
¿Que?¿Que entregaras o haras? Desarrollo de un sistema web bajo arquitectura Java EE clasica (JSP + Servlets + JDBC), desplegado sobre Apache Tomcat, que incluye:
  • Gestion de productos, ingredientes y recetas.
  • Ordenes de produccion (para stock o vinculadas a un pedido).
  • Registro de pedidos y punto de venta presencial (POS).
  • Reportes de ventas por rango de fechas y de stock bajo.
  • Tienda web publica: catalogo, carrito, checkout (recojo o delivery) y seguimiento de pedidos.
  • Panel de repartidor para pedidos delivery.
Documentacion asociada: informe tecnico, diagrama Entidad-Relacion (DER), prototipos de interfaz (3 alternativas), manual de usuario basico.
¿Cuando?¿Cuando haras la entrega? La entrega se realizara conforme al cronograma del ciclo 2026-II, reflejado en el diagrama de Gantt del informe tecnico:
  • Fase 1: Gestion del proyecto - Lean Canvas y Acta de Constitucion (semanas 1-2).
  • Fase 2: Analisis y diseno - SRS, DER, prototipos de interfaz (semanas 2-4).
  • Fase 3: Configuracion del entorno - JDK, Tomcat, MySQL, NetBeans (semanas 3-4).
  • Fase 4: Desarrollo de todos los modulos del sistema (semanas 5-10).
  • Fase 5: Pruebas e integracion (semanas 11-13).
  • Fase 6: Documentacion final y sustentacion (semanas 13-15).
¿Para quien?¿Para quien estas haciendo este trabajo y quienes son tus patrocinadores? Es el cliente principal, es decir, la empresa donde se ejecuta el proyecto. En este caso, la empresa "Dulce Momento" (pasteleria artesanal, escenario academico).

Usuarios finales:
  • Administrador del negocio y personal de ventas.
  • Personal de cocina y de reparto (delivery).
  • Clientes de la tienda web.
Patrocinador academico: curso de Desarrollo Web Integrado, UTP.
¿Por que?¿Por que este proyecto es necesario? Problema actual:
  • Control manual del inventario de ingredientes y productos, con margenes de error.
  • Pedidos recibidos por WhatsApp de forma desordenada, sin historial ni seguimiento de estado.
  • Falta de reportes en tiempo real para la toma de decisiones (stock bajo, ventas del dia).
Beneficios esperados (solucion):
  • Reduccion de perdidas por inventario mal gestionado (mermas no registradas).
  • Trazabilidad completa: cada movimiento de stock queda auditado (quien, cuando, por que).
  • Reportes automatizados de ventas y alertas de stock bajo.
  • Nuevo canal de venta propio (tienda web) ademas del canal presencial.
¿Donde?¿Donde se usara el producto o servicio? Entorno de implementacion:
  • Aplicacion web accesible desde cualquier navegador moderno (personal interno y clientes).
  • Desplegada sobre Apache Tomcat 11, con MySQL 8 como motor de base de datos.
Requisitos tecnicos:
  • Servidor con JDK 21 y Apache Tomcat 11 instalados.
  • Base de datos MySQL 8 accesible por red local (o en la nube a futuro).
  • Navegador web moderno (Chrome, Edge, Firefox) del lado del cliente.
¿Como?¿Como alcanzaras los objetivos y como controlaras y haras monitoreo del proyecto? Mediante un equipo de desarrollo de 4 integrantes que utilizara herramientas colaborativas y una metodologia de trabajo iterativa por modulos. Se consideraran riesgos como perdida de avances no respaldados y errores introducidos al integrar modulos; se hara seguimiento continuo para garantizar el cumplimiento de los objetivos.
  • Enfoque de desarrollo: iterativo e incremental, un modulo a la vez (productos → ingredientes → pedidos → produccion → reportes → tienda web), con pruebas manuales de cada modulo antes de integrarlo al siguiente.
  • Gestion de riesgos: respaldo del script de base de datos (schema.sql) antes de cambios de esquema; pruebas de cada flujo transaccional (venta, produccion, cancelacion) antes de darlo por terminado.
  • Herramientas: GitHub para control de versiones; NetBeans + Maven para desarrollo y build; MySQL Workbench para administracion de base de datos; el diagrama de Gantt del curso para seguimiento del cronograma.
