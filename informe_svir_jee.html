1. Introduccion y objetivos

1.1 Descripcion general de la aplicacion web

Presentacion de la empresa

Dulce Momento es una pasteleria artesanal (escenario academico) dedicada a la elaboracion y venta de tortas, mousses, pancitos y galletas, tanto por atencion presencial como por pedidos via WhatsApp y, a partir de este proyecto, mediante una tienda web propia.

Mision: Ofrecer productos de reposteria artesanal frescos y de calidad, con un servicio de pedido y entrega simple, rapido y confiable.

Vision: Consolidarse como la pasteleria de referencia del barrio, ampliando su canal de venta digital y su capacidad de produccion sin perder el control del inventario ni la trazabilidad de cada pedido.

Planes futuros: Incorporar mas canales de venta (redes sociales), ampliar el equipo de reparto y ofrecer reportes de rentabilidad por receta.

Problematica actual

  • Control manual del inventario de ingredientes y productos, con margenes de error y mermas no siempre registradas.
  • Pedidos recibidos por WhatsApp de forma desordenada, sin historial ni seguimiento de estado.
  • Sin visibilidad en tiempo real de que ingrediente esta por agotarse ni de que se debe producir cada dia.
  • Ausencia de un canal de venta en linea propio (solo boca a boca y WhatsApp).

Alcance del sistema

El sistema cubre: autenticacion y roles de personal, gestion de productos e ingredientes, recetas, ordenes de produccion, pedidos y punto de venta presencial, reportes de ventas y stock, panel de repartidor, y una tienda web publica (catalogo, carrito, checkout con recojo o delivery, seguimiento de pedidos). Queda fuera del alcance de esta primera version: pasarelas de pago en linea y facturacion electronica ante SUNAT.

1.2 Objetivos del sistema

Objetivo general: Desarrollar un sistema web bajo la arquitectura Java EE clasica (JSP + Servlets + JDBC), desplegado sobre Apache Tomcat, que permita a la pasteleria Dulce Momento gestionar su inventario, produccion, ventas y pedidos de forma centralizada y trazable.

Objetivos especificos:

  • Implementar una capa de acceso a datos en JDBC puro (sin ORM), con una clase de conexion singleton y transacciones controladas manualmente.
  • Construir vistas dinamicas en JSP (directivas, scriptlets, expresiones) para cada modulo del sistema.
  • Diseñar un modelo de datos normalizado en MySQL que refleje correctamente el dominio del negocio.
  • Implementar control de acceso basado en roles (ADMIN, VENTAS, COCINA, REPARTIDOR) mediante un filtro de Servlet.
  • Habilitar un canal de venta publico (tienda web) independiente del panel administrativo interno.

2. Arquitectura del entorno y configuracion

2.1 Servidor Web / Web Container

El sistema se despliega como un archivo .war sobre Apache Tomcat 11 (implementacion de Jakarta Servlet 6.0 / JSP 3.1), instalado de forma independiente (no embebido). El despliegue se realiza copiando el .war generado por Maven a la carpeta webapps/ de Tomcat; el propio Tomcat lo descomprime y lo publica en la ruta de contexto /svir-jee.

Configuracion relevante de Tomcat utilizada:

  • Puerto HTTP: 8080 (por defecto).
  • Puerto de apagado (shutdown): 8005.
  • CATALINA_HOME: C:\apache-tomcat-11.0.24.

El modelo de datos esta normalizado en Tercera Forma Normal (3FN) sobre MySQL 8, con 11 tablas. Las claves foraneas mantienen la integridad referencial entre pedidos, productos, ingredientes, recetas, producciones y sus respectivas auditorias de movimiento de stock.

4.2 Clases de conexion JDBC

La clase ConexionBD implementa el patron Singleton: una unica instancia conoce los parametros de conexion (leidos de db.properties) y el driver com.mysql.cj.jdbc.Driver, y expone un metodo que entrega una Connection nueva en cada llamada (JDBC no garantiza que una Connection sea segura para uso concurrente entre hilos).

public final class ConexionBD {

    private static final ConexionBD INSTANCIA = new ConexionBD();

    private final String url;
    private final String usuario;
    private final String password;

    private ConexionBD() {
        Properties props = new Properties();
        try (InputStream in = ConexionBD.class.getClassLoader()
                .getResourceAsStream("db.properties")) {
            props.load(in);
        } catch (IOException e) {
            throw new IllegalStateException("Error leyendo db.properties", e);
        }
        this.url = props.getProperty("db.url");
        this.usuario = props.getProperty("db.user");
        this.password = props.getProperty("db.password");
        Class.forName(props.getProperty("db.driver"));
    }

    public static ConexionBD getInstancia() { return INSTANCIA; }

    public Connection obtenerConexion() throws SQLException {
        return DriverManager.getConnection(url, usuario, password);
    }
}

Pruebas de conexion exitosas

La conexion fue probada de forma exhaustiva durante el desarrollo: creacion, edicion y eliminacion logica de productos e ingredientes; registro de pedidos con descuento real de stock dentro de una transaccion (Connection.setAutoCommit(false) + commit()/rollback()); y generacion/finalizacion/cancelacion de ordenes de produccion verificando el consumo y devolucion de ingredientes. 5. Desarrollo con JSP y Servlets basicos

Las vistas usan directivas de pagina (<%@ page %>, <%@ include %>), scriptlets (<% %>) y expresiones (<%= %>) para renderizar datos que el Servlet deja como atributos del request. Ejemplo (fragmento de dashboard.jsp):

<%@ page contentType="text/html;charset=UTF-8" language="java" %>
<%@ page import="com.svir.jee.model.DashboardResumen" %>

    DashboardResumen resumen = (DashboardResumen) request.getAttribute("resumen");

<div class="stat-card">

5.2 Manejo de parametros (POST/GET)

Cada modulo usa un unico Servlet que resuelve todas sus variantes de pantalla mediante el parametro action (patron "Front Controller" simple). Ejemplo real de ProductoServlet, capturando datos de un formulario HTML enviado por POST:

@WebServlet("/app/productos")
@MultipartConfig(maxFileSize = 5 * 1024 * 1024)
public class ProductoServlet extends HttpServlet {

    protected void doPost(HttpServletRequest req, HttpServletResponse resp) {
        String idParam = req.getParameter("id");
        Producto p = new Producto();
        p.setNombre(req.getParameter("nombre"));
        p.setPrecio(new BigDecimal(req.getParameter("precio")));
        p.setStock(Integer.parseInt(req.getParameter("stock")));
        // ... crea o actualiza segun si idParam viene vacio ...
    }
}

6. Evidencias y codigo fuente

6.1 Fragmentos de codigo clave

Ver ConexionBD.java en la seccion 4.2 y ProductoServlet.java en la seccion 5.2. A continuacion, un fragmento adicional que muestra el manejo de una transaccion JDBC completa (creacion de un pedido, descontando stock y registrando el movimiento de auditoria):

Connection con = ConexionBD.getInstancia().obtenerConexion();
con.setAutoCommit(false);
try {
    // ... insertar pedido, insertar cada linea de detalle_pedido ...
    productoDAO.descontarStock(con, productoId, cantidadAtendida);
    movimientoDAO.registrar(con, movimientoVenta);
    con.commit();
} catch (SQLException e) {
    con.rollback();
    throw e;
} finally {
    con.setAutoCommit(true);
    con.close();
}
